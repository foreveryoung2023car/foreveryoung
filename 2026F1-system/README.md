# 2026 F1 鈴鹿接駁後端

與前端 `2026F1/` 同級。後端以 Google Apps Script 提供 JSON API，以一份 Google 試算表儲存班次、訂單和報到狀態。

1. 建立 Google 試算表和 Apps Script 專案。將 `Code.gs` 與 `appsscript.json` 複製進專案。
2. 在 Apps Script「專案設定 → 指令碼屬性」設定 `SHEET_ID`（試算表網址中的 ID）、`STAFF_KEY`（發給司機和調度員的通行碼）、`CHECKIN_SECRET`（另一組隨機密鑰，只留在後端）。
3. 執行 `setupSheets` 並授權，建立 `Vehicles` 和 `Bookings` 工作表。將資料貼入表頭下方，維持純文字格式以保留電話前面的零。
4. 部署為網頁應用程式，以部署者身分執行，允許所有人存取，以便乘客不用 Google 帳號即可查詢。先用測試表驗證。
5. 將 `2026F1/config.js` 的 `API` 改成部署得到的 `/exec` 網址，並把 `USE_NEW_BACKEND` 設為 `true`。前端仍需另外發布，現有 GitHub Pages 流程只發布 `kimono/`。

## 資料格式

- `Vehicles` 每日每車一列。同一天的車牌須唯一，`vid` 是顯示車號。車輛有跑哪一程，就填該程的集合點和預定時間。實際出發、抵達欄可留白，由司機頁更新。
- `Bookings` 每日每筆訂單一列。同一天的訂單編號須唯一，使用英數字、底線、連字號或句點。`pax` 填乘客人數。去回程車牌各自對應當天的 `Vehicles`；未購買的行程留白。報到狀態欄預設留白。
- 日期用 `0326` 到 `0329`，時間用 24 小時制 `HH:mm`。乘客自助報到僅限對應的 2026 年乘車日（日本時間）；工作人員可以補登歷史資料。
- 乘客用電話與姓名查詢自己的訂單。查詢回傳的簽章只可確認該訂單當天的行程。工作人員通行碼可查看全部車輛和名單，並更新報到與車輛狀態。請保持試算表為私人，避免在前端寫入通行碼或密鑰。
